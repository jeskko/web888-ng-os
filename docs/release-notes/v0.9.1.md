A security update of web888-ng's SD card image: **a current 6.18 kernel**,
**newer system packages**, and **fewer of them**. web888d is unchanged
(v0.12.0). Test images, for owners who have their Web-888 at hand.

**Updating from v0.9.0:** the admin page's **Update** tab offers v0.9.1
(it looks once a day, or press **Look for a release**): **Install**, then
**Reboot now**. The unit keeps its settings and goes back to v0.9.0 by
itself if the new system doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.1/docs/updates.md)).

**From v0.3.0 to v0.8.0** (SSH, with an `ssh_key` in `web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.9.1/web888-ng-v0.9.1.raucb
reboot
```

Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.1/docs/testing-the-sd-image.md).

## New since v0.9.0

Known vulnerabilities (CVEs) in the image, as the project's daily scan
counts them (`.github/workflows/cve.yml`): **7214 → 140**, of CVSS 7.0
or more **3197 → 37**.

* **Kernel 6.18.63:** Xilinx's 2026.2 kernel (6.18.40) with the Linux
  6.18 stable updates up to 6.18.63 on top (was 6.18.10). Kernel CVEs
  7064 → 113. Where Xilinx carries its own version of a driver the
  stable changes don't apply to, Xilinx's is kept; none of those drivers
  is in use on a Web-888 (`meta-web888/recipes-kernel/linux/`).
* **Newer packages:** curl 8.23.0, expat 2.10.0, PCRE2 10.49, zlib 1.4,
  acl 2.4.0, attr 2.6.0 (from OpenEmbedded-Core's development branch),
  glibc and the rest of OpenEmbedded-Core at their latest wrynose fixes.
* **Less in the image.** Yocto added its default features to ours, so
  earlier images carried Bluetooth, Wi-Fi, 3G (ofono), NFC (neard), NFS
  (rpcbind, which listened on port 111) and X11 libraries, none of them
  used. They are gone, and so is systemd-machined. **Wi-Fi:** nothing in
  `web888.txt` ever set it up; a unit someone put on Wi-Fi by hand needs
  its cable.
* CVEs that can't reach the image are recorded as such, with the reason,
  in the recipes: U-Boot's network stack (U-Boot is built without
  networking), OpenSSH's server and client (only its SFTP server is
  installed, for `scp`; the SSH server is Dropbear), util-linux's user
  mounts.
* Left with CVSS 7.0 or more outside the kernel: three in BusyBox's
  shell and `awk` (a crash from crafted input; no fix upstream yet).
* Nothing else changes: web888d v0.12.0, the same bitstreams, driver and
  settings.

## Tested

In the emulator (web888-ng-hw `emu/tests/`), on this release's build:
* the image's boot through the boot ROM, both slots and `web888.txt`
  (`sd-image.sh`), with no bitstream line and with `bitstream =
  standard`;
* **the update from the published v0.9.0 image to this release's bundle**
  (`ota.sh`), with a power cut mid-install and a bad update rolled back.

On a Web-888: the kernel since 2026-11-13 08:48 UTC and this release's
build since 14:45 UTC, chain-loaded from the stock firmware rather than
from this card: the channelizer, FT8 and FT4 skimmers on 20 bands, live
DX spots, the map, Kiwi clients.

## Known limits

* The channelizer (the default since v0.7.0) has not yet run from a card
  image on a board; `bitstream = standard` in `web888.txt` brings back
  the standard bitstream.
* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Updates leave `BOOT.BIN` and `u-boot.img` alone (they aren't A/B); a
  release that needs new ones will say so. This one doesn't: U-Boot's
  only fix here is in its network code, which ours is built without.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* The bitstream setting in the admin pages has no effect unless
  `web888.txt` says `bitstream = standard` (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* The stock firmware's extensions and the Kiwi browser UI are not
  included.

## Files

* `web888-ng-sd-v0.9.1.img.xz`: the card image; `.img.bmap` for
  `bmaptool`
* `web888-ng-v0.9.1.raucb`: the update bundle, for units on v0.3.0 or
  later
* `SHA256SUMS`
* `web888-ng-sd-v0.9.1.spdx.json` and `.manifest`: the software in the
  image and its licences (SPDX), with Yocto's CVE assessments. Sources:
  the recipes in this repository at the tag, and the upstream projects
  they name.
