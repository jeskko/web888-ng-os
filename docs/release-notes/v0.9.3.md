**Safe mode:** a unit whose system keeps failing to start no longer
tries again forever, out of reach. It comes up without the radio, with
the network, SSH and the admin page, so it can be repaired or updated
from where you are. With web888d v0.12.1. Test images, for owners who
have their Web-888 at hand.

**Updating from v0.9.0 or later:** the admin page's **Update** tab
offers v0.9.3 (it looks once a day, or press **Look for a release**):
**Install**, then **Reboot now**. The unit keeps its settings and goes
back to the previous system by itself if the new one doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.3/docs/updates.md)).

**From v0.3.0 to v0.8.0** (SSH, with an `ssh_key` in `web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.9.3/web888-ng-v0.9.3.raucb
reboot
```

Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.3/docs/testing-the-sd-image.md).

## New since v0.9.2

**Safe mode** ([docs/safe-mode.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.3/docs/safe-mode.md)):

* **When:** neither root slot has tries left (each gets three boots to
  bring web888d up), or `web888.txt` says `safe = yes`.
* **What runs:** the network as `web888.txt` sets it up, SSH, the
  tunnels, the watchdog, the update system, and web888d's pages with a
  "Safe mode" notice and the reason. Not the SDR driver's use, the
  bitstream, the receivers, the skimmers and their uploads, or HPSDR.
* **One more address that is always the same: `169.254.88.8`**, on top
  of the configured ones. If the network settings or the DHCP server are
  what went wrong, a computer on the same network segment still reaches
  the unit there (with an address in 169.254.x.x of its own).
* **It stays** in safe mode over reboots and power cuts, until you end
  it: **Leave safe mode** on the admin page, `web888-safe leave` over
  SSH, or installing an update. Both slots then have their tries again.
* **The boot loader's part** (a newly written card only, see below):
  with no tries left it used to refill them and reset, in a loop. It now
  boots a slot with the SDR driver kept from loading, taking the two
  slots in turn in case one doesn't boot at all.
* **Cards written with an earlier release** keep their boot loader
  (updates don't replace it), and get the rest: safe mode on the last
  try of the last slot, for that boot. To get the whole of it, write
  this card image (keep a copy of `web888.txt`).

**web888d v0.12.1:** `serve --safe`, the notice and the button
([its notes](https://github.com/jeskko/web888-ng/releases/tag/v0.12.1)).

Nothing else changes: the same kernel, packages, bitstreams and
settings as v0.9.2.

## Tested

In the emulator (web888-ng-hw `emu/tests/`), on this release's build:
* the image's boot through the boot ROM, both slots and `web888.txt`,
  and **safe mode**: asked for in `web888.txt`, then by the boot loader
  with no tries left in either slot (web888d without the radio, the
  driver not loaded, the fixed address, the tries not refilled), and out
  of it with `web888-safe leave` (`sd-image.sh`), with no bitstream line
  and with `bitstream = standard`;
* **the update from the published v0.9.2 image to this release's bundle**
  (`ota.sh`), with a power cut mid-install and a bad update rolled back.

Not on a Web-888: the unit that ran the last releases' systems is
chain-loaded from the stock firmware, without the boot loader or the
root slots that safe mode is about.

## Known limits

* The channelizer (the default since v0.7.0) has not yet run from a card
  image on a board; `bitstream = standard` in `web888.txt` brings back
  the standard bitstream.
* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Updates leave `BOOT.BIN` and `u-boot.img` alone (they aren't A/B).
  This release's boot loader has a part in safe mode (above); a unit
  updated from an earlier release runs fine with its old one.
* Safe mode has run in the emulator, not yet on a board.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* The bitstream setting in the admin pages has no effect unless
  `web888.txt` says `bitstream = standard` (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* No Wi-Fi since v0.9.1.
* The stock firmware's extensions and the Kiwi browser UI are not
  included.

## Files

* `web888-ng-sd-v0.9.3.img.xz`: the card image; `.img.bmap` for
  `bmaptool`
* `web888-ng-v0.9.3.raucb`: the update bundle, for units on v0.3.0 or
  later
* `SHA256SUMS`
* `web888-ng-sd-v0.9.3.spdx.json` and `.manifest`: the software in the

  the recipes in this repository at the tag, and the upstream projects
  they name.
