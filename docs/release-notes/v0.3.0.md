web888-ng's SD card image with **updates over the network**, **tunnels
to the Internet** and web888d v0.6.0 (**JTTY decoding** in the browser).
Test images, for owners who have their Web-888 at hand.

v0.2.0 has booted from an SD card on a Web-888 (a tester's board,
2026-10-30): the boot, the network, the open bitstream and the right RF
frequencies. v0.3.0 adds to that system without changing how it boots.

**Coming from v0.1.0 or v0.2.0:** those have no updater, so write this
card image once (keep a copy of `web888.txt`). From v0.3.0 on, later
releases install over the network.

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.3.0/docs/testing-the-sd-image.md).

## New since v0.2.0

* **Updates over the network** (RAUC), with each release's
  `web888-ng-<version>.raucb`. Over SSH:
  ```sh
  rauc install https://github.com/jeskko/web888-ng-os/releases/download/<version>/web888-ng-<version>.raucb
  reboot
  ```
  * The bundle is streamed from the URL into the root slot not in use;
    the receiver keeps running meanwhile. Only bundles signed by the
    project and made for the Web-888 are accepted.
  * After the reboot the new slot has three tries. If web888d doesn't
    come up, the unit goes back to the old slot.
  * Settings stay: `web888.txt`, the admin password, the configuration
    partition and SSH host keys.
  * Details: [docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.3.0/docs/updates.md).
    One bundle updates both the standard and the channelizer image.
* **Tunnels**: `web888.txt` can connect the unit out to a public server,
  so the receiver can be reached from the Internet without opening a
  port on the router.
  * Four clients: frp (contributed, thanks to j0uni), Cloudflare Tunnel
    (cloudflared, no server of your own), rathole and chisel.
  * Their tokens and passwords are taken off the card, as with the
    admin password. Visitors keep their own addresses in web888d's
    per-address limits.
  * Off unless set up:
    [docs/tunnels.md](https://github.com/jeskko/web888-ng-os/blob/v0.3.0/docs/tunnels.md).
* **web888d v0.6.0**: JTTY decoding in the browser (the footer's JTTY
  button: common dials, messages with UTC time and RF frequency).
  [Release notes](https://github.com/jeskko/web888-ng/releases/tag/v0.6.0).

Two images, the same system; only the shipped `web888.txt` differs:
`web888-ng-sd-v0.3.0.img.xz` (the standard bitstream, 12 receivers) and
`web888-ng-sd-v0.3.0-channelizer.img.xz` (`bitstream = channelizer`,
experimental, up to 32 receivers). The bitstreams are as in v0.2.0.

## Tested

* In the emulator:
  * the boot through the boot ROM, both slots, web888.txt and the
    tunnel clients staying off without settings
    (web888-ng-hw `emu/tests/sd-image.sh`);
  * updates: a streamed install and its boot, a power cut during an
    install, a bad update rolled back (`emu/tests/ota.sh`).
* The tunnels' setup on a host (web888-setup with each tunnel's
  settings). frp has also run through a real server on a Web-888 (the
  contributor's test). cloudflared, rathole and chisel haven't been
  tried against real servers yet.
* JTTY: in a browser against generated signals, not yet on live ones.

## Known limits

* Updates leave `BOOT.BIN` and `u-boot.img` alone (they aren't A/B); a
  release that needs new ones will say so.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* With `bitstream = channelizer`, the bitstream setting in the admin
  pages has no effect (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second
  more delay; the status bar links to the HTTPS address of the same page
  (the browser warns once about the unit's own certificate).
* A tunnel makes the admin pages public too: set a strong
  `admin_password`.
* KiwiSDR clients and the stock firmware's extensions are not supported.

## Files

* `web888-ng-sd-v0.3.0.img.xz`, `web888-ng-sd-v0.3.0-channelizer.img.xz`:
  the card images; `.img.bmap` for `bmaptool`
* `web888-ng-v0.3.0.raucb`: the update bundle (for units already on
  v0.3.0 or later)
* `SHA256SUMS`
* `web888-ng-sd-v0.3.0.spdx.json` and `.manifest`: the software in the
  images and its licences (SPDX). Sources: the recipes in this
  repository at the tag, and the upstream projects they name.
