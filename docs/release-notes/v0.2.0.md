web888-ng's SD card image, now also with the **channelizer bitstream**:
the whole HF band split into 30 kHz bins in the FPGA, so the number of
receivers is limited by the CPU (up to 32 at once) instead of the
standard bitstream's 12. **Test images, for owners who have their
Web-888 at hand**: neither has run from an SD card on a board yet (see
"Known limits").

Two images, the same system; only the shipped `web888.txt` differs:

* `web888-ng-sd-v0.2.0.img.xz`: the standard bitstream (12 receivers),
  as in v0.1.0.
* `web888-ng-sd-v0.2.0-channelizer.img.xz`: `bitstream = channelizer`
  set in `web888.txt`. **Experimental.** Change the line to
  `bitstream = standard` on the card to go back to the standard one.

Your unit is not changed: everything is on the new card. To go back to
the stock firmware, power off and put your original card back in.

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.2.0/docs/testing-the-sd-image.md).

## New since v0.1.0

* The channelizer bitstream ([web888-ng-hw v0.3.0](https://github.com/jeskko/web888-ng-hw/releases/tag/v0.3.0)),
  chosen with `bitstream = channelizer` in `web888.txt`. web888d then
  runs in bins mode: receivers, skimmers and HPSDR take their channels
  from the bins and the FPGA's tuner, the full-band waterfall comes from
  the FPGA's power line, and zoomed views from per-bin FFTs. It has run
  on a remote Web-888 since 2026-10-29 (FT8 skimmers on ten bands, load
  tests up to 32 listeners), chain-loaded rather than from this card.
* The standard bitstream stays web888-ng-hw v0.2.0's, the
  hardware-tested one.

## What's in it

* Boot loader: U-Boot 2026.01 (SPL with the PS7 setup of the open FPGA
  design, then U-Boot). It sets the ADC clock (Si5351, 122.88 MHz) and
  boots one of two system copies on the card, falling back to the other
  if one keeps failing.
* Linux 6.18 (AMD/Xilinx LTS) with the open `web888-sdr` driver (both
  bitstreams) and a device tree for the Web-888.
* [web888d v0.5.0](https://github.com/jeskko/web888-ng/releases/tag/v0.5.0):
  the web receiver (waterfall, AM/SSB/CW/FM), FT8, FT4 and WSPR skimmers
  with PSKReporter and WSPRnet uploads, HPSDR Protocol 1, admin pages.
* `web888.txt` on the card: admin password, DHCP or static network,
  hostname, an SSH key, the bitstream. `web888-setup.log` next to it says
  what was applied.

## Known limits

* **Not yet booted from an SD card on a board.** The boot loader's
  memory and clock setup matches the stock firmware's, but this is the
  first time it meets a board. If the unit doesn't come up, a serial
  console log helps most.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* With `bitstream = channelizer`, the bitstream setting in the admin
  pages has no effect (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second
  more delay; the status bar links to the HTTPS address of the same page
  (the browser warns once about the unit's own certificate).
* No updates over the network yet: a new release means writing the card
  again (settings made in the admin pages are lost then; keep a copy of
  `web888.txt`).
* KiwiSDR clients and the stock firmware's extensions are not supported.

## Files

* `web888-ng-sd-v0.2.0.img.xz`, `web888-ng-sd-v0.2.0-channelizer.img.xz`:
  the card images; `.img.bmap` for `bmaptool`
* `SHA256SUMS`
* `web888-ng-sd-v0.2.0.spdx.json` and `.manifest`: the software in the
  images and its licences (SPDX). Sources: the recipes in this
  repository at the tag, and the upstream projects they name.
