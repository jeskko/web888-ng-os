**Updating from v0.9.0 or later:** the admin page's **Update** tab

back to the previous system by itself if the new one doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.14.0/docs/updates.md)).

**From v0.3.0 to v0.8.0** (SSH, with an `ssh_key` in `web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.14.0/web888-ng-v0.14.0.raucb
reboot
```

Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of

## New since v0.13.0

* **Linux 6.18.64:** Xilinx's 2026.2 kernel with the stable updates up
  to 6.18.64 (was 6.18.63). The rest of the CVE scan of 2026-11-20 was
  checked against what the image builds and runs, and recorded in the
  recipes (`CVE_STATUS`): code that isn't built (SMB, other
  architectures and KVM, file systems and drivers the board doesn't
  have, huge pages, userfaultfd, KSM), CAN (the board's controllers are
  off), swap (none is set up), OpenSSL's QUIC, DTLS, DANE and CMS with
  CRL checks, glibc's `glob()` and an iconv module the image doesn't
  install.
* **chrony** keeps the system clock instead of systemd-timesyncd: the
  same four Google NTP servers, combined and checked against each other;
  a drift file on the configuration partition, so after a reboot the
  clock runs at the right rate before the first answer (the board has
  no battery-backed clock); and a reference-clock socket
  (`/run/chrony.web888.sock`, refid `LF`) through which a later web888d
  hands chrony the LF time-code stations it decodes (DCF77, MSF, RBU,
  and the EFR teleswitch stations' time telegrams): with them the clock
  keeps time without a network. While NTP is reachable it stays the
  main source. `chronyc sources` (as root) shows them.

web888d, the UI and the bitstreams are the same as in v0.13.0
(web888d v0.16.0, which doesn't use the socket yet).

## Tested

In the emulator (web888-ng-hw `emu/tests/`), on this release's build:
* the image's boot through the boot ROM, both slots, `web888.txt`, safe
  mode, and chronyd running in place of timesyncd with its socket and
  drift directory (`sd-image.sh`, 56 checks; its first run found the
  drift directory missing, fixed before the release);
* **the update from the published v0.13.0 image to this release's
  bundle** (`ota.sh`, 21 checks), with a power cut mid-install and a bad
  update rolled back.

On a Web-888 (the developer's remote unit, chain-loaded): this release's
chrony binaries in place of timesyncd, synchronised to the NTP servers,
and fed through the socket by a development web888d from the unit's own
time-code stations (DCF77, RBU, DCF39), whose offsets agreed with NTP
within about a millisecond (DCF39 and RBU within 0.3 ms). The 6.18.64
kernel has run in the emulator only.

## Known limits

* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* The boot loader update (v0.10.0) has run in the emulator only. Writing
  it is optional.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Safe mode has run in the emulator, not yet on a board.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* No Wi-Fi since v0.9.1.
* The stock firmware's extensions and the Kiwi browser UI are not
  included.
