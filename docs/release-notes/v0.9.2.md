A small security follow-up to v0.9.1: one more kernel fix, and every
known vulnerability of CVSS 7.0 or more left in the image is now
assessed, with the reason recorded. web888d is unchanged (v0.12.0).
Test images, for owners who have their Web-888 at hand.

**Updating from v0.9.0 or v0.9.1:** the admin page's **Update** tab
offers v0.9.2 (it looks once a day, or press **Look for a release**):
**Install**, then **Reboot now**. The unit keeps its settings and goes
back to the previous system by itself if the new one doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.2/docs/updates.md)).

**From v0.3.0 to v0.8.0** (SSH, with an `ssh_key` in `web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.9.2/web888-ng-v0.9.2.raucb
reboot
```

Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.2/docs/testing-the-sd-image.md).

## New since v0.9.1

Known vulnerabilities (CVEs) of CVSS 7.0 or more in the image, as the
project's daily scan counts them: **37 → 0** (v0.9.0: 3197).

* **Kernel:** the fix for CVE-2026-72397 (PMBus core), which 6.18.63
  doesn't have yet.
* **Not built:** 28 of the kernel's were in code this kernel doesn't
  build (BPF syscalls, SMB, network file systems, OCFS2, AMD GPU
  drivers, SCTP, netfilter, IPsec, framebuffers, ...). Each was checked
  against the kernel's configuration and the Makefiles that build the
  fix's files; the recipe names the deciding option.
* **Built, but out of an attacker's reach here,** recorded with the
  reason (SPDX: "inline mitigations already exist" or "vulnerable code
  cannot be controlled by an adversary"):
  * CVE-2021-3864 (core dumps of SUID programs' descendants): core
    dumps are off (`fs.suid_dumpable = 0`, no dump handler), and root is
    the only account that can log in.
  * CVE-2026-53091 (crafted GSO packets in the transmit path): such
    packets would have to come from TUN/TAP or virtio, which aren't
    built, or a raw packet socket, which only root and systemd-networkd
    can open; the unit doesn't forward.
  * CVE-2026-89584 (direct I/O with crafted vectors on a bio-based block
    device): the only such device is dm-verity during an update, and
    only root can open it.
  * BusyBox CVE-2026-38752, -38753, -38755 (crashes from a crafted awk
    program or shell script): only root can run commands, and nothing
    hands outside input to awk or the shell.
* The SBOM (`.spdx.json`) carries these assessments, so other scanners
  read them too. Lower-rated CVEs (about 100, most in the kernel) are
  not assessed one by one.
* Nothing else changes: web888d v0.12.0, the same bitstreams, driver and
  settings.

## Tested

In the emulator (web888-ng-hw `emu/tests/`), on this release's build:
* the image's boot through the boot ROM, both slots and `web888.txt`
  (`sd-image.sh`), with no bitstream line and with `bitstream =
  standard`;
* **the update from the published v0.9.1 image to this release's bundle**
  (`ota.sh`), with a power cut mid-install and a bad update rolled back.

On a Web-888: v0.9.1's system (the same but for the PMBus fix, a driver
for chips the Web-888 doesn't have) since 2026-11-13, chain-loaded from
the stock firmware rather than from this card.

## Known limits

* The channelizer (the default since v0.7.0) has not yet run from a card
  image on a board; `bitstream = standard` in `web888.txt` brings back
  the standard bitstream.
* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Updates leave `BOOT.BIN` and `u-boot.img` alone (they aren't A/B); a
  release that needs new ones will say so. This one doesn't.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* The bitstream setting in the admin pages has no effect unless
  `web888.txt` says `bitstream = standard` (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* No Wi-Fi since v0.9.1.
* The stock firmware's extensions and the Kiwi browser UI are not
  included.

## Files

* `web888-ng-sd-v0.9.2.img.xz`: the card image; `.img.bmap` for
  `bmaptool`
* `web888-ng-v0.9.2.raucb`: the update bundle, for units on v0.3.0 or
  later
* `SHA256SUMS`
* `web888-ng-sd-v0.9.2.spdx.json` and `.manifest`: the software in the
  image and its licences (SPDX), with Yocto's CVE assessments. Sources:
  the recipes in this repository at the tag, and the upstream projects
  they name.
