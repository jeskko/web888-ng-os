web888-ng's SD card image with **zoomed waterfalls computed in the
FPGA**: with the channelizer bitstream, many listeners can each have
their own zoomed view. Test images, for owners who have their Web-888 at
hand.

**Updating from v0.3.0 or later** (SSH, with an `ssh_key` in
`web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.6.0/web888-ng-v0.6.0.raucb
reboot
```

The unit keeps its settings and goes back to the previous system by
itself if the new one doesn't come up ([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.6.0/docs/updates.md)).
Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.6.0/docs/testing-the-sd-image.md).

## New since v0.5.0

* **The channelizer bitstream of web888-ng-hw v0.4.0**
  ([release notes](https://github.com/jeskko/web888-ng-hw/releases/tag/v0.4.0)),
  used with `bitstream = channelizer` in `web888.txt`. It has a zoom
  engine: the FPGA computes the spectra of zoomed waterfalls. The driver
  is the one from that release.
* **web888d v0.9.0** ([release notes](https://github.com/jeskko/web888-ng/releases/tag/v0.9.0)):
  * zoomed views take their spectra from the zoom engine. On a Web-888,
    16 listeners each with their own 480 kHz view ran at 20 lines a
    second without an audio gap; before, the CPU was full;
  * 15.36 MHz views are sharper (15 kHz display bins), and grainier.
* **A fix for the channelizer from the card:** the device tree gave the
  driver register windows too small for the channelizer's registers, so
  earlier card images could not have run it. They are a page each now.
  See "Tested" below: this has not been tried on a board yet.
* The default HF bitstream (v0.2.0's, 12 receivers) is unchanged, and
  nothing changes for units that use it apart from web888d v0.9.0.

## Tested

In the emulator (web888-ng-hw `emu/tests/`):
* the image's boot through the boot ROM, both slots and `web888.txt`
  (`sd-image.sh`);
* **the update from the published v0.5.0 image to this release's bundle**
  (`ota.sh`): a streamed install, the reboot into the new slot, a power
  cut during an install, and a bad update rolled back.

The emulator's FPGA is the standard HF one: it does not run the
channelizer.

On a Web-888: the channelizer bitstream, the driver and web888d of this
release have run on one unit since 2026-11-11, some hours with load
tests, under a system chain-loaded from the stock firmware and not from
this card. **The channelizer has not been run from a card image on a
board.** If you try `bitstream = channelizer`, please report how it
goes.

## Known limits

* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Updates leave `BOOT.BIN` and `u-boot.img` alone (they aren't A/B); a
  release that needs new ones will say so.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* With `bitstream = channelizer`, the bitstream setting in the admin pages
  has no effect (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* The stock firmware's extensions and the Kiwi browser UI are not
  included.

## Files

* `web888-ng-sd-v0.6.0.img.xz`: the card image; `.img.bmap` for
  `bmaptool`
* `web888-ng-v0.6.0.raucb`: the update bundle, for units on v0.3.0 or
  later
* `SHA256SUMS`
* `web888-ng-sd-v0.6.0.spdx.json` and `.manifest`: the software in the
  image and its licences (SPDX). Sources: the recipes in this repository
  at the tag, and the upstream projects they name.
