web888-ng's SD card image with web888d v0.12.0: **live DX cluster spots**
on the spectrum and in the spot list, **a map of the stations heard**,
and **OS updates from the admin page**, so this is the last update that
needs SSH. Test images, for owners who have their Web-888 at hand.

**Updating from v0.3.0 or later** (SSH, with an `ssh_key` in
`web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.9.0/web888-ng-v0.9.0.raucb
reboot
```

From v0.9.0 on, the admin page's **Update** tab does this: it shows when
a newer release is out, installs it with its progress on the page, and
reboots into it. The unit keeps its settings and goes back to the
previous system by itself if the new one doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.0/docs/updates.md)).
Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

**How to try it:** [docs/testing-the-sd-image.md](https://github.com/jeskko/web888-ng-os/blob/v0.9.0/docs/testing-the-sd-image.md).

## New since v0.8.0

* **web888d v0.12.0** ([release notes](https://github.com/jeskko/web888-ng/releases/tag/v0.12.0)):
  * **Live DX spots** from [Spothole](https://spothole.app) (DX clusters
    by default): as labels on the spectrum (**Labels: DX spots**) and in
    the **Spots** list, which now shows the skimmers' decodes, the DX
    spots or both.
  * **A map** (**Map**): the skimmers' spots, your browser's own
    FT8/FT4/WSPR decodes and the DX spots, with lines from the receiver;
    great circle, globe or Mercator, with the greyline. Click (on a
    phone: tap twice) a station to tune to it. The world map comes from
    the unit itself.
  * **The Update tab** in the admin page (above).
  * **Fewer false decodes reported:** "RR73" is no longer taken for a
    locator, and an uncertain FT8/FT4 decode goes to PSKReporter only
    once the same call is heard again on the band within 15 minutes.
  * **Metrics:** `/metrics` is up to date (`doc/metrics.md` in
    web888-ng, with a Grafana dashboard). **Changed:** it now answers
    only the addresses in `[web] metrics_allow` (none by default): add
    your Prometheus there if you scrape it.
  * The panel buttons moved to the top bar, the status bar holds still,
    and the phone layout's panels fit the screen.
* **New outside connections**, both on by default and both can be turned
  off in the admin pages: the unit follows Spothole's spot stream
  (`[dxspots]`) and looks for a new release on GitHub once a day
  (`[update]`). Neither sends anything about the unit but the requests
  themselves.
* Nothing else changes: the same bitstreams (the HF channelizer of
  web888-ng-hw v0.4.0, the VHF one of v0.5.0, HF and VHF of v0.2.0), the
  same driver and settings.

## Tested

In the emulator (web888-ng-hw `emu/tests/`), on this release's build:
* the image's boot through the boot ROM, both slots and `web888.txt`
  (`sd-image.sh`), with no bitstream line and with `bitstream =
  standard`;
* **the update from the published v0.8.0 image to this release's bundle**
  (`ota.sh`), with a power cut mid-install and a bad update rolled back;
* the Update tab on this image: it finds RAUC and the release list on
  GitHub, and shows the running version and both slots.

The Update tab's whole path (look, install from GitHub, reboot, the new
slot marked good) ran in the emulator with web888d v0.12.0 on the v0.8.0
image, twice. The emulator's FPGA is the standard HF one: it runs neither
the channelizer nor VHF.

web888d v0.12.0's features have run on a Web-888 since 2026-11-12, under
a system chain-loaded from the stock firmware rather than from this card
(so without the Update tab), with skimmers on 20 bands, live DX spots and
the map.

## Known limits

* The channelizer (the default since v0.7.0) has not yet run from a card
  image on a board; `bitstream = standard` in `web888.txt` brings back
  the standard bitstream.
* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Updates leave `BOOT.BIN` and `u-boot.img` alone (they aren't A/B); a
  release that needs new ones will say so.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* The bitstream setting in the admin pages has no effect unless
  `web888.txt` says `bitstream = standard` (`web888.txt` decides).
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* The stock firmware's extensions and the Kiwi browser UI are not
  included.

## Files

* `web888-ng-sd-v0.9.0.img.xz`: the card image; `.img.bmap` for
  `bmaptool`
* `web888-ng-v0.9.0.raucb`: the update bundle, for units on v0.3.0 or
  later
* `SHA256SUMS`
* `web888-ng-sd-v0.9.0.spdx.json` and `.manifest`: the software in the
  image and its licences (SPDX). Sources: the recipes in this repository
  at the tag, and the upstream projects they name.
